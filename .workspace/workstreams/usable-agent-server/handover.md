# Usable-agent-server handover

Status: Waves 0-5 are closed; D30 deployment design and the first central per-Agent upgrade core are
implemented. The remaining deployment milestone is installer/enrollment UX, fleet rollout policy/UI,
release packaging/signing, and the final cross-platform freeze evidence.

The authoritative order is `phases.md`. The previous deployment-first A1–A10 plan is retired because it
conflicted with `docs/ROADMAP.md`. The accepted UI shell/routing contract has graduated into D25,
architecture §11, `docs/design/ui.md`, the roadmap, and the walkthrough.

## Closed Wave-1 surface

The real Kestrel host now serves deterministic OpenAPI plus protected system, Agent, audit, build, and
queue reads. The public projections use explicit revisions, stable ordering, bounded opaque cursors,
conditional ETags, and RFC 9457 errors. Agent active-build links distinguish the child build ID from
its parent matrix resource.

## Closed Wave-2 Agent contract

AgentHub now negotiates explicit v1 capabilities and durable generations, platform collectors report
bounded typed static facts, SQLite preserves fenced observation/capability state, and Agent REST reads
project freshness plus current/observation provenance. Legacy Agents are explicit and drained from new
work while retaining the completion lane for adopted work.

## Closed Wave-3 desired-configuration foundation

The controller now owns a normal managed-local system-Git repository, validates bounded canonical
candidate trees, commits through compare-and-swap before activation, and durably materializes revision
sets with last-known-good recovery under migrations v5-v6. Desired activation is fenced against build
admission, exact conflicts replay durably, and a hosted monitor converges external local-Git heads. The
first and only desired schema currently
implemented outside administration is Agent `spec.enabled` at `.vivarium/agents/{id}.yaml`; its public
`/api/v1/agents/{id}/settings` GET/PUT surface uses strong configuration ETags, idempotency, audit, and
explicit desired/applied status. The administration path additionally owns canonical User and direct
built-in RoleBinding documents. Names, custom properties, groups/custom roles, providers/images,
Projects/Build Configurations, server policy, remote authority, and review workflows remain future work.

## Closed Wave-4 public build/results foundation

The controller now has object-scoped blob staging and Agent/human transfer grants, idempotent build
submit/cancel, durable resumable build SSE, and immutable build payload/artifact references. The live CLI
build flow consumes REST/SSE. Migration v8 and the bounded TRX adapter durably persist reports, test
definitions, occurrences, typed projection failures, no-report/partial state, and restart catch-up while
retaining raw TRX authority. A real-Kestrel acceptance proves two independent Agents can run two matrix
cells concurrently on distinct Agent identities. The full 298-test gate is green.

## Closed Wave-5 administration/RBAC foundation

Migrations v9-v11 now persist the resumable administration saga, Git User/direct built-in RoleBinding
projections, and private named-user credentials. A fresh controller rotates and reveals one local
bootstrap value, exchanges it into a setup-only session, survives restart/session loss, and supports
host-local reissue or pre-commit abandon. Completion writes the User and `SYSTEM_ADMIN` binding in one
Git commit, reconciles that exact revision, then activates the private password verifier and closes all
setup access. Named panel login and credential-generation fencing use the shared evaluator.

Break-glass recovery is never generated by an ordinary active restart. A host-local issue operation
creates one expiring recovery value; its dedicated REST exchange creates a bounded Superuser session
that survives restart and loses all normal API authority immediately on local revoke. Legacy admin and
submit credentials keep only their previous adapter scopes. Groups, service accounts, PATs, custom
roles, project ancestry/shared-pool rules, general identity REST, setup UI/local CLI, and legacy-token
removal remain explicit follow-on work rather than hidden Wave-5 claims. The final serial root gate is
green: 298 passed, 10 platform-only skips, 0 failed (308 total).

## Closed central-upgrade core (D30)

Migration v12, immutable per-RID package storage/catalog import, authenticated Agent-scoped delivery,
durable fenced upgrade/drain state, busy-Agent completion, restart recovery, exact three-phase health
confirmation, one-shot LKG rollback, public REST, and CLI commands now run. Real bootstrap + real Agent
child-process tests prove successful activation and failed-candidate rollback on macOS/Linux; a separate
two-Agent test proves one draining Agent does not block its peer.

## Immediate execution

Continue serially under the reduced-memory budget. For the deployment goal, build stamped enrollment
bundles/installers and release catalog generation next, then fleet canary/rolling orchestration over the
existing per-Agent operation. Windows real-process, bad/truncated download, interrupted activation,
D21 installer authenticity, signing, and previous-release compatibility remain release gates. Preserve
the transitional ControlPlane until remaining list/authorize management methods have REST parity.

## Deployment decisions retained for Wave 6+

- First installation uses a verified stamped ZIP with a seed Agent package.
- Before authorization, bootstrap never requests a manifest.
- After authorization, bootstrap reuses the existing protected Agent credential for narrow authenticated
  package reads; a second local package credential is not introduced without real OS-principal isolation.
- Digest, not version alone, identifies/activates a package.
- Durable upgrade operation/shared lease precedes bootstrap restart work.
- D30 adopted the numbered refinement and authorizes the current bootstrap implementation; keep it
  change-controlled until the remaining freeze evidence closes.

The first physical proof target remains the local `osx-arm64` host unless intentionally changed; that
choice affects platform evidence, not the architecture or two-Agent gate.
